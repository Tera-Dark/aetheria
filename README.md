# ✦ AETHERIA · 活体壁纸

> **Generative Living Wallpaper · 每一帧都是循环相位的纯函数**

两件纯代码生成的实时影像，运行在浏览器里。不是视频，不是 GIF——是一个全屏的、
会在你桌上挂一整天的程序化作品。零素材，零外部资源：所有像素都是数学。

```bash
npm install
npm run dev        # http://localhost:5180
```

在线版本：**<https://tera-dark.github.io/aetheria/>**（由 `.github/workflows/pages.yml`
在每次 push 到 `main` 时自动构建发布）

`Space` / `←→` / 点击画面 切换作品 · `Q` 画质（锁定一档后再按回到自动）· 鼠标不动 2.4 秒后界面消失

## 这版重写解决了什么

上一版（`72b039a`，Remotion）把作品做成了**可导出的影片**。那是一次架构误判：
交付物是"一个会跑很久的全屏程序"，不是"一个能渲染出 mp4 的文件"。Remotion 的
价值在逐帧渲染与擦洗，而这两件事对壁纸都不存在——没人要擦洗，也没人等你渲染。

于是推翻重写，换成一套为"长时间运行"设计的运行时。

| 问题 | 现在的做法 |
|---|---|
| 渲染器把一切都当离线任务 | `src/core` 只做实时的事：一个时钟、一条 rAF、一条后期链 |
| 相位靠 `this.time += dt` 累积 | 相位由单一原点每帧重算，场景内部不做任何累加 |
| 无法验证循环是否真的闭合 | `npm run seam` 把相位钉死、锁死画质、关掉颗粒，然后**逐像素相减** |
| 画质只影响分辨率 | 画质档同时改分辨率、体积积分步数、bloom 与景深 |
| 切换作品是硬切 | 双源合成，真正的交叉淡入；淡入结束后立刻释放第二套 HDR 缓冲 |

## 唯一需要记住的规则

**场景是相位的函数，不是动画。**

```ts
update(info: FrameInfo): void   // info.phase ∈ [0,1)
```

在 `update` 里禁止出现：

- `Math.random()` —— 需要随机就用实例的 `iSeed`（索引派生，确定）
- `+=` 形式的累积 —— 需要"动起来"就写 `sin(TAU * phase * n)`，`n` 取整数
- `Date.now()` / 帧间隔 —— 需要绝对时间就用 `elapsed`，且只用于性能计数
- 任何 DOM 事件 —— 交互只允许影响**取景**（相机视差），绝不能影响场景状态

这条规则一次性买到四件事：回绕无缝、第 10000 帧和第 10 帧完全一致、没有任何东西
会泄漏（所以运行时长无上限）、任意相位都能单独渲染（所以可抓帧、可录像、可验证）。

### 回绕处最容易踩的坑

`q += phase * 0.42` 这种**线性漂移**在回绕时会把整个场瞬移。而值噪声一个格
约等于数百个世界单位，所以 0.42 不是"轻微挪动"，是换了一整片地形——静止帧看不出
来，一个循环结束就露馅。

`GLSL_CYCLIC` 里的 `driftCircle()` 采样的是一条**闭合圆周**：场在整个周期里持续
变化，回到起点时值与导数都对得上。

```glsl
vec2 driftCircle(float phase, float radius, float squash){
  float a = phase * TAU;
  return vec2(cos(a) * radius, sin(a) * radius * squash);
}
```

同理，抖动必须是**屏幕空间静态**的。相对图像运动的噪声读起来像镜头上的污渍，
而不是空气——而且它让首帧和末帧无法比较，`seam` 就失去意义了。用
`GLSL_DITHER` 里的 interleaved gradient noise，hash 噪声会结块，结块在体积积分
里表现为雾里的斑。

## 验证：`npm run seam`

无缝循环是唯一一条**看**不出来”的要求。所以它必须可测量。

```bash
npm run dev                    # 另开一个终端
npm run seam                   # 两个作品各测一次
```

页面加载后脚本会：锁死画质档 → 关掉胶片颗粒 → 把相位钉在 0 → 快照 → 钉在 0.999
→ 快照 → 在页内逐像素相减。

```
月落雾谷   seam φ=0 vs φ=0.999 → mean 0.0844 · p99.5 2   · peak 148  [OK]
深海流光   seam φ=0 vs φ=0.999 → mean 0.2855 · p99.5 12  · peak 163  [OK]
```

mean 是 8-bit 单位下的平均绝对差，容差 1.0。`peak` 之所以还有一百多，是因为
触手是亚像素宽的 ribbon：边缘像素在两帧之间落进或落出覆盖范围，局部的差就是
全幅。这种差异在软边上看不见，`p99.5` 才是该看的指标。

同一个脚本还负责抓帧和抓中间的过渡：

```bash
npm run shoot                              # 每个作品各抓 2 个相位
node scripts/shoot.mjs --scene 1 --phases 0,0.25,0.5,0.75
node scripts/shoot.mjs --transition        # 交叉淡入的中间态
node scripts/shoot.mjs --scene 1 --seam --tolerance 0.5   # 更严的门槛
```

`?capture=1` 会打开 `preserveDrawingBuffer`，这是像素回读的前提。它带来每帧一次
拷贝，所以只在抓帧时开。页面还会暴露 `window.__aetheria`（`setPhase` / `setFade` /
`lockQuality` / `grade` / `snap` / `diff`）——**运行中的时钟无法和自己比较**，
要比较两个相位，就必须能把相位钉住。

## 目录结构

```
src/
  core/
    loop.ts          循环契约：整数谐波、呼吸、闭合漂移、周期值噪声、缓动
    scene.ts         场景接口与注册表（唯一的扩展点）
    camera.ts        相机架：三个周期自由度 + 指针视差
    renderer.ts      Stage：时钟、rAF、resize 去抖、像素预算
    performance.ts   p50/p95 画质调速器，带死区与不对称步长
    postprocess.ts   HDR + 景深 + bloom 金字塔 + ACES + 分级 + 颗粒
    app.ts           应用外壳：场景生命周期、淡入、输入、检查接口
  shaders/
    common.ts        GLSL 片段库：hash / noise / ridged / 周期噪声 / 抖动 /
                     相函数 / ACES / 分级
  scenes/
    moonlit-vale/    01 · 月落雾谷
    abyssal-bloom/   02 · 深海流光
  main.ts            启动器：注册作品、接线 HUD、暴露检查钩子
scripts/shoot.mjs    无头 Chrome 抓帧 + seam 量化
```

加一个新作品 = 写一个目录 + 在 `main.ts` 里加一行 `registerScene`。

## 两件作品

### 01 · 月落雾谷 · MOONLIT VALE　`96s`

参考场景，同时是引擎的压力测试：山体、雾、光柱全部在**同一个 raymarch 里**，
所以它们之间的遮挡关系是正确的。分层贴片或高度场平面能给���层次感，但雾永远会
错误地盖在最上面——那一个瑕疵就是程序化风景显得廉价的原因。

- 低悬的月把光斜射过雾海。岩石几乎全是剪影，**分隔山脊线的是雾，不是明暗**。
- 相机脚下有一片盆地。没有它，高度场会在相机所在位置抬起地面，把画面下半整个
  封死——山脉必须只存在于远处，山谷才成立。
- 空气透视是免费的：颜色是光线**真正穿过霾的距离**的函数。
- 草丛 2600 束实例化，两个弯曲模式（整体倾倒 + 叶尖鞭打）都由相位派生。
- 尘埃在体积光柱里才亮，所以光柱里有东西在飘，而不是一片均匀的尘雾。

### 02 · 深海流光 · ABYSSAL BLOOM　`84s`

整个场景围绕一个物理事实组织：**在深度上，阳光是唯一光源**。所以每个主体的顶部
被照亮、底部沉入蓝黑。把光打反、或者把水照得均匀，它就立刻变成游泳池而不是
海洋。这一条决定占了这件作品与游泳池之间的全部差别。

- **伞缘向内卷到腹面以下。** 这是水母和圆顶的分界线；没有它，动物就没有可以被
  观察的"底面"，读起来是一顶蘑菇帽。
- **钟罩是薄膜，不是朗伯体。** 你看到的是穿过它的光：包裹漫反射给肉体，前向透射
  给背面。暗面用沟槽而不是画上去的线——平直的一条线贴在光滑的面上就是贴纸。
- **收缩快、回弹慢。** 上升沿上取 3.5 次幂把能量挤进收缩，回弹就自然变软。触手
  的摆动**滞后**于收缩，而伞缘的裂瓣又比收缩再滞后一点；这几级延迟是"身体"与
  "缩放"之间的全部差别。
- **群体是手工摆的，不是哈希撒的。** 一个主体、一个配重，其余的把视线在两者之间
  引过去。哈希撒出来的群体没有构图。
- 每个个体的生物发光强度、伞高、裂瓣数、收缩频率都不同，否则十只水母就是同一个
  模型盖了十个章。
- 远景只靠水的吸收变蓝变绿——所以一只橙色发光的水母在远处是蓝的。

## 性能与长跑

- **像素预算，而不是 `devicePixelRatio`。** 4K 屏 DPR 2 是 3300 万像素，每一个都要
  过一个全屏 fragment shader。`resolveDpr()` 在预算内选 DPR。
- **画质调速器看 p50/p95，不看瞬时值。** 对单帧尖峰做反应的调速器会来回震荡，
  而抖动的壁纸比 45fps 的壁纸干扰得多。
- **升档比降档慢。** 过量配置再回收才是"抽动"的来源。
- **模拟用 clamp 过的 `dt`，界面计时用没 clamp 的。** 切后台一小时的标签页不该
  给场景一个巨大的步长；但 1.8 秒的淡入必须是 1.8 秒的墙钟时间，否则在 4fps 的
  机器上它要跑一分钟。
- **后期链的所有中间缓冲在 `setSize` 里一次分配。** 每帧分配是长跑的内存增长。
  唯一例外是交叉淡入的第二套缓冲——它在淡入开始时分配、结束时释放。
- **场景切换完整 dispose。** 壁纸的泄漏只会在几小时后才显形。

## 已知不足

诚实记录，避免下次踩同样的坑：

- **月落雾谷**：地形是 sphere tracing，命中点对步长极敏感，所以 seam 的 mean 是
  0.08 而不是 0——山脊线上有亚像素抖动。看不见，但别指望它是 0。草在画面最下沿
  有一道略硬的边界，近处的叶片没有景深虚化。
- **深海流光**：光柱偏"柔和"而不是"成束"，因为 46 米水深下的真实丁达尔效应本来
  就该很散——想要更明确的束状得加对比度，代价是画面变平。触手仍然偏"刷子"，
  它们靠顶点着色器摆动，没有沿长度的曲率变化。海雪几乎看不见。
- **共性**：两件都还没有音频。`SceneInstance.audio()` 与 `AudioBus` 接口都在，
  `nullAudioBus` 是默认实现，所以接上合成层不需要动任何场景。
- **共性**：竖版（9:16）没有适配。相机构图是按 16:9 摆的，`COLONY` 里的坐标是
  手工构图，换纵横比需要重新摆而不是重新缩放。

本仓库只包含当前这一版。重构过程（Canvas 壁纸画廊 → Remotion 影片 → 现在的 WebGL
运行时）没有随仓库公开；下面这段"已知不足"里提到的两个 seam 数字，就是那三次重写
各自留下的验收记录。
